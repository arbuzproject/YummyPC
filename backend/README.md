# YummyPC backend

Серверная часть клиента: скрывает токены API от клиента и добавляет внешние балансеры,
которые ненадёжно резолвятся на десктопе (ссылки с IP-привязкой и т.п.).

## Что делает

| Ручка | Назначение |
|---|---|
| `GET /health` | статус сервиса, размер индекса, статистика кэша |
| `* /yani/{path}` | прозрачный прокси к API: подставляет серверный `X-Application` и `Lang`, прокидывает `Authorization` пользователя, кэширует GET |
| `GET /v1/sources/{animeId}/{episode}` | внешний балансер: находит релиз по MAL id или названию и отдаёт прямую HLS-ссылку с качествами |
| `GET /v1/sources/{animeId}` | сопоставленный релиз и список серий (для проверки матчинга) |

## Конфигурация

Секреты читаются из окружения (файл `/etc/...env`, в репозиторий не попадает):

- `YANI_X_APPLICATION` — токен приложения yani (выдаётся сервисом);
- `YANI_BASE` — базовый URL API (по умолчанию публичный);
- `ANILIBRIA_BASE` — адрес API балансера;
- `PORT` — порт прослушивания.

Никаких адресов, железа и расположения в репозитории нет — развёртывание у каждого своё.

## Развёртывание

Стандартная схема: systemd-юнит для бинарника, reverse proxy (nginx/Caddy) с TLS,
например через Let's Encrypt. Скриптов и адресов в репозитории нет — только исходники.

```bash
cd backend
go build -o yummypc-backend .
YANI_X_APPLICATION=... ./yummypc-backend
```

## Структура

- `main.go` — HTTP-маршруты, health, graceful shutdown;
- `yani.go` — прокси к API с кэшем и подстановкой секретов;
- `anilibria.go` — внешний балансер: индекс релизов, матчинг, HLS;
- `match.go` — нормализация названий и поиск релиза (есть тесты `match_test.go`);
- `cache.go` — простой TTL-кэш в памяти.
